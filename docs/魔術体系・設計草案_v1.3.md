# 魔術体系・設計草案 v1.3

対象： Minecraft 統合版（Bedrock Edition）アドオン
設計方針： 属性相性、術式構築、精霊との契約、魔力管理、魔法同士の干渉を組み合わせ、戦闘中の判断と読み合いを重視する魔術体系を構築する。

## 0. 仕様の管理方針

本草案では、各仕様を次の三段階に分類する。

* 確定： 採用が決定した仕様。
* 暫定： 設計上の基準として置いているが、調整の余地がある仕様。
* 未決定： 今後の設計で具体化する必要がある仕様。

既存の仕様と新しい決定が矛盾する場合は、新しい決定を優先する。

# 第I部　魔術の基本構造

## 1. 魔術の基本原理

魔術とは、世界に存在する法則を利用し、現象に干渉する技術である。

魔術の性能は、単純なレベルや魔力の量だけでは決まらない。以下の要素が相互に作用する。

* 術式の構造と構築難度
* 精霊との契約と魔力供給能力
* 魔力の消費・供給・管理
* 魔導書と杖の使い分け
* 属性・形状・状態・運動特性
* 魔法同士の衝突・貫通・拡散・軌道変化
* 術者の判断と戦闘中の行動

魔術体系の中心は、単純な火力の大小ではなく、術式の選択、魔力管理、属性相性、発動タイミング、対抗手段の読み合いにある。

## 2. 単純魔術と複雑魔術

### 2.1 単純魔術

古代文明から存在する、魔術の基礎となる術式。

単純魔術は必ずしも弱い魔術ではない。術式の構造が単純であることと、戦闘能力が低いことは別である。

### 2.2 複雑魔術

複数の機能要素を組み合わせた術式。

構成要素の例：

* 属性
* 形状
* 状態
* 運動・軌道
* 貫通
* 拡散
* 誘導
* 押し出し
* 分裂

単純魔術と複雑魔術は、強弱ではなく術式の構造によって分類する。

# 第II部　精霊・契約・魔力

## 3. 精霊と契約

### 3.1 精霊の定義

精霊は、世界の法則が意識を持つ存在として現れたもの。

術者は精霊と契約することで、その力を借りて魔術を行使する。

一体の精霊が複数の属性に関係する場合もある。

### 3.2 契約構造

契約精霊には、次の役割を想定する。

* 主契約精霊： 安定した供給や得意分野を担う。
* 補助契約精霊： 術式の柔軟性や追加機能を支える。

契約可能数、契約条件、精霊ごとの個性は未決定。

### 3.3 精霊の研究と発見

精霊や魔術についての知識は、以下の方法で得られる構想とする。

* 遺跡や古文書の調査
* 精霊の観察・実験
* 精霊との交流や契約
* 既存魔術の改良
* 複数の機能要素の組み合わせ

研究・発見・習得を実際のゲームシステムとしてどう表現するかは未決定。

## 4. 魔力と供給方式

### 4.1 魔力の役割

魔力は、魔術の発動や維持に用いる資源である。

魔術の発動には所定量の魔力を必要とする。

魔力と精霊の力の厳密な関係、最大値、自然回復、発動コスト、維持費は未決定。

### 4.2 精霊からの供給

確定仕様

* 精霊は一定速度で魔力を供給する。
* 供給能力は契約ごとに異なる。

供給能力は、精霊との契約を選ぶ際の重要な差別化要素となる。

### 4.3 味方からの供給

確定仕様

* 味方は供給操作を行っている間、一定速度で魔力を渡す。

供給操作中の移動制限、距離制限、供給対象の選択、複数人からの同時供給、供給の中断条件は未決定。

### 4.4 魔力不足の処理

以下の挙動は未決定。

* 発動に必要な魔力が不足している場合
* 詠唱中に魔力が不足した場合
* 発動中に維持費を支払えなくなった場合
* 供給を受けながら詠唱する場合
* 術式崩壊時の魔力損失以外に、詠唱失敗時の損失を設けるか

## 5. 魔力・構築負荷・作用量・威力の区別

四つの概念を混同しないようにする。

### 5.1 魔力

魔術を発動・維持するための資源。

### 5.2 構築負荷

術式を構築・維持・制御する難しさを表す値。

### 5.3 作用量

魔法同士の干渉や衝突に関係する値。衝突時の作用量減少、貫通、残存率による弱体化などに用いる。

### 5.4 威力

主に生物などの対象へ与えるダメージの基礎値。

作用量が大きい魔法が、必ずしも対象に大きなダメージを与えるとは限らない。

### 5.5 未決定事項

* 作用量と威力の関係
* 各値の基礎値・上限・計算式

# 第III部　術式構築・媒体・詠唱

## 6. 魔導書と杖

魔導書と杖は、同じ魔術を発動できるが、得意分野が異なる。

### 6.1 魔導書

* 複雑な術式の構築・調整に向く。
* 精密な制御を得意とする。
* 詠唱は比較的遅い。
* 詠唱中の移動に制約がある。

### 6.2 杖

* 素早い発動や反応に向く。
* 事前に構築した複雑な魔術を素早く発動する運用に向く。
* 比較的自由に移動できる。

媒体ごとの詠唱時間、移動制限、構築可能な術式の範囲は未決定。

## 7. 詠唱と発動

### 7.1 詠唱時間

詠唱時間は、術式の複雑さと使用する媒体によって変化する。

構築負荷を詠唱時間にどう反映するかは未決定。

### 7.2 視線と発射方向

確定仕様

* 詠唱中は視点を動かせる。
* 魔法の発射方向は、詠唱開始時ではなく詠唱完了時点の視線方向で決まる。

これにより、詠唱中の視線操作を戦術の一部として扱える。

## 8. 術式崩壊

### 8.1 定義

術式崩壊とは、詠唱中に構築している術式そのものが破綻し、魔法の発動が不可能になる現象である。

一時的な詠唱中断とは異なり、崩壊した術式をそのまま立て直して再開することはできない。

### 8.2 崩壊時の確定仕様

* 構築中の術式は完全に崩壊する。
* 詠唱進捗は0%になる。
* 崩壊した術式の詠唱を途中から再開することはできない。
* それまでに消費した魔力は戻らない。
* 同じ魔法を再び使用するには、最初から詠唱し直す必要がある。

術式崩壊は、時間だけでなく、すでに消費した魔力も失う重大な失敗である。

### 8.3 崩壊の発生条件

以下は未決定。

* 被弾時に必ず崩壊するか、条件付きで崩壊するか
* 攻撃の種類や威力によって崩壊条件が変化するか
* 魔導書と杖で崩壊のしやすさに差を設けるか
* 崩壊を防ぐ特性や手段を設けるか
* 詠唱以外の状況でも術式崩壊が起こり得るか

旧案の「術式を短時間で立て直し、少し後退した進捗から再開する」という仕様は、術式崩壊には適用しない。

# 第V部　魔法同士の干渉

## 13. 衝突処理の基本原則

魔法同士が衝突したとき、双方の作用量を減少させる。

基本方針：

* 作用量は時間経過や飛行距離だけでは減少しない。
* 魔法同士の衝突など、定義された条件で作用量が減少する。
* 摩耗などの持続的な接触効果は、通常の衝突処理と分けて定義する。
* 同一の衝突を複数回処理しない。
* 双方の作用量減少は、衝突前の値を基準に同時に計算する。

## 14. 通常衝突による作用量減少

魔法Aと魔法Bが衝突した場合、以下の式を用いる。

```
lossA = B.interference × matchup_multiplier(B → A)

lossB = A.interference × matchup_multiplier(A → B)

forceA' = max(0, forceA - lossA)

forceB' = max(0, forceB - lossB)
```

ここで、force は作用量を示す。実装時には変数名を統一する。

### 14.1 相性倍率（暫定）

* 有利：1.25
* 中立：1.00
* 不利：0.75

条件付き相性では、形状・状態・特性などに応じて倍率や処理を決定する。

これらの数値は暫定値であり、テスト後に調整する。

## 15. 作用量の残存率と弱体化

作用量の残存率に応じて、魔法の性能を段階的に低下させる。

```
r = forceCurrent / forceMax
```

| 残存率 r | ダメージ倍率 | 速度倍率 | 射程倍率 |
|---|---|---|---|
| r >= 0.75 | 1.00 | 1.00 | 1.00 |
| r >= 0.50 | 0.80 | 0.90 | 0.90 |
| r >= 0.25 | 0.60 | 0.75 | 0.75 |
| 0 < r < 0.25 | 0.30 | 0.50 | 0.50 |
| r = 0 | 0 | 0 | 0 |

数値と境界条件は暫定。

作用量がゼロになった魔法は終了する。

## 16. 貫通

### 16.1 基本仕様

貫通特性を持つ魔法は、相手の魔法の作用量が残っていても、条件を満たせば突破できる。

貫通には追加の作用量コストを必要とし、突破後も弱体化する。

### 16.2 貫通コスト（暫定）

```
C_pen = C_base × M_shape × M_state
```

* C_pen：貫通に必要な追加作用量コスト
* C_base：貫通側の基礎コスト
* M_shape：対象の形状による倍率
* M_state：対象の状態による倍率

合成倍率は暫定的に0.5〜2.0の範囲に制限する。

### 16.3 形状倍率（暫定）

| 対象の形状 | 倍率 |
|---|---|
| 細長い・薄い | 0.75 |
| 球体 | 1.00 |
| 広範囲・拡散 | 1.25 |
| 壁状・厚い障壁 | 1.50 |

### 16.4 状態倍率（暫定）

| 対象の状態 | 倍率 |
|---|---|
| 砂・粉塵など分散しやすいもの | 0.60 |
| 液体 | 0.80 |
| 通常の状態 | 1.00 |
| 硬い岩石など | 1.40 |

### 16.5 処理順序

1. 衝突直前の双方の作用量を記録する。
2. 通常の衝突による作用量減少を計算する。
3. 通常の減少後、貫通側に必要なコストを支払えるか判定する。
4. 支払える場合は追加コストを差し引き、方向を維持して突破する。
5. 支払えない場合は追加コストを差し引かず、通常の衝突結果に従う。
6. 通常の衝突処理で作用量がゼロになった魔法は終了し、貫通できない。

貫通に失敗しても、必ず魔法そのものが消滅するわけではない。

## 17. 衝突後の方向と挙動

衝突後の挙動は、属性・形状・状態・特性に応じて決定する。

基本結果：

* 直進を維持する
* 拡散する
* 軌道を変える
* 相殺・終了する

衝突角度は補助的な要素とする。

貫通魔法は原則として進行方向を維持する。ただし、固有の性質によって例外を設けられる。

一回の衝突で適用する主要な結果は一つとする。結果の優先順位と例外条件は未決定。

## 18. 特性と作用量の関係

* 貫通： 突破時に追加の作用量を消費する。
* 拡散： 魔法の広がり方や効果範囲を変化させる。
* 軌道変化： 進行方向を変更する。
* 誘導： 対象へ向かうように軌道を調整する。
* 押し出し： 相手の魔法を押し動かす。
* 分裂： 残存する作用量を複数の魔法へ分配する。

分裂によって作用量を新たに生成してはならない。

分裂後の作用量・威力・速度・射程の配分方法は未決定。

# 第VI部　実装方針と今後の課題

## 19. Minecraft BE版の実装構造

システムを機能ごとに分割する。

* SpellData：魔法の属性・形状・状態・特性・数値
* AttributeRules：属性相性と倍率
* CollisionDetector：魔法同士の衝突検出
* InteractionResolver：衝突結果・作用量減少・貫通・方向変化
* SpellUpdater：飛行・追尾・速度・射程・寿命
* SpellEffects：ダメージ・押し出し・拡散などの効果
* CastingSystem：詠唱・術式崩壊・発動
* ConstructionSystem：構築負荷・特性の組み合わせ・構築制限
* ManaSystem：魔力管理・精霊からの供給・味方からの供給

### 19.1 実装上の注意

* 対象とするMinecraft BE版のバージョンとScript APIを確認する。
* 未確認のAPI仕様を前提にしない。
* 同じ衝突を複数回処理しない。
* 継続接触による毎フレームの再衝突を防ぐ。
* 魔法同士の全組み合わせを無条件に毎回判定しない。
* 魔力や作用量を二重に消費しない。
* 魔法の内部計算と演出を分離し、調整しやすくする。
* 術式崩壊時に詠唱進捗と魔力損失が正しく適用されるようにする。

本魔術体系は、単なるレベル制や属性相性だけのシステムではない。

術式の構造、精霊との契約、魔力供給、構築負荷、媒体、形状・状態・運動、作用量、特性の組み合わせ、そして術者の判断を連動させる。

術式崩壊では、詠唱時間だけでなく消費済みの魔力も失われる。この損失によって、強力な魔法を選ぶことには明確なリスクが生まれる。

最終的には、プレイヤーが強い魔法を一つ作れば終わりなのではなく、相手の魔術を読み、状況に合った術式を選び、魔力と行動を管理しながら戦うことが重要になるシステムを目指す。
